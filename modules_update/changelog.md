# 更新日志

## v1.8.2（182）

### 核心更新

- 守护进程统一为 Rust 版 `AppOptRs`，移除旧 C 守护、C 回退标记及重复构建链路；模块安装、看门狗、App 状态检测和诊断查询均只使用 Rust 版，异常退出后继续自动拉起。
- 新增 eBPF fork/exec 进程事件发现，可更快感知目标进程和线程变化；eBPF 不可用、事件丢失或读取失败时，自动回退现有 `pid_cache.tsv + /proc` 校验，不影响基础兼容性。
- 优化守护运行时缓存与文件监控，规则、UID 映射和匹配索引仅在配置变化时重建，并保留周期完整校验，减少重复解析、无效扫描和待机唤醒。
- 新增自定义 Rust cpuset 运行组，可在 App 设置中编辑并保存到 `calib_policy.conf`；名称经过三端校验，保存后自动重启守护生效，不改变线程规则的核心分配。
- Aya 精简子模块改为跟随远端 `main` 分支更新；构建脚本只输出四个 ABI 的 `AppOptRs`，继续保留 FPS eBPF、SurfaceFlinger 降级和进程查询降级能力。
- 修复区块内单条规则的 CPU 值、线程名或进程名无效时连带丢弃整个区块的问题；Rust 现在只忽略问题成员，其余线程、子进程和兜底规则继续生效。
- 完善规则格式转换与写回：无效规则保留为旧版单行等待用户修正，带进程前缀歧义的线程名不会在原作者或扩展区块中被误解为子进程。
- 修复部分 Root 环境下命令失败或超时后被降级路径重复执行的问题，保留超时前已读取的输出，并区分 `su -c` 不兼容与命令自身失败。
- 修复高低帧率档位切换后动态调度长期停留在增强状态的问题；稳定帧率会重新学习基线并恢复临时参数，校准策略核心列表与默认值同时按设备实际存在的 CPU 保存。

# 更新日志

## v1.8.5（185）

- 重构 Rust 绑核校验与恢复：通过 `sched_getaffinity` 读取实际核心，写入后立即复核，并按 PID/TID `starttime` 防止复用误绑；发现厂商服务或 task profile 抢写时会重新迁入 AppOpt cpuset 并恢复规则核心，亮屏前后台每 2 秒、熄屏每 10 秒校验一次。
- 优化常驻扫描功耗：日常进程发现继续使用 `pid_cache.tsv + /proc` 增量路径，规则健康与前台生命周期改为对应应用的包级扫描；深度复核按进程错峰并设置每轮预算，恢复性全量扫描调整为亮屏 60 秒、熄屏 5 分钟。
- 待校准页面新增“启动后自动开始校准”开关；首次开启使用强制阅读 5 秒的底部提示，明确启动阶段负载偏高可能降低准确性，并在确认目标应用进入前台后才自动开始采样。
- 合并前台助手与 Rust 守护的 `service.sh` 保活循环，避免开机后出现两个同名脚本进程，同时保留二者独立检测和异常重启能力。
- 修复最高负载候选未达到 `best_thread` 双阈值时直接放弃最高性能核心的问题；现在会继续按负载顺序选择第一个达标线程，动态编号线程仍以通配规则稳定命中。
- 统一 App 与 Rust 的规则容错：函数区块支持逗号分隔的多段 CPU 核心列表，区块内单条 CPU 值无效时只忽略问题成员，不再连带隐藏其余有效规则。
- 修复历史记录认领文件损坏后持续阻塞新记录导入的问题，异常文件会保留为 `.invalid` 供诊断；旧数据库中只有单个样本的负载曲线也会正确完成压缩迁移。
- 修复系统 DownloadManager 下载成功后清理任务时连同模块 ZIP 一起删除的问题；刷入前先将文件复制到 App 管理路径，并完善非 ASCII Binder 字符串的 UTF-16 编码兼容。
